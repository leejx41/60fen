# 「60分」执行力 App —— 机制设计 v0.3

> **核心理念**：60 分是抽象代称。它真正的含义是——**在行动开始前，拆掉那些以"完美"为伪装的阻力。**
>
> **一句话定位**：不是帮你把事情做好，是帮你在想放弃的那一刻，把自己的论证拆开给你看。

---

## 本版变更（相对 v0.2）

| 变更 | 内容 | 原因 |
|---|---|---|
| **借口输入方式** | 预置选项 → **完全自由输入** | 预置理由覆盖不了真实；且用户原话是产品最锋利的武器 |
| **给出最小动作的方式** | 单一规则库 → **三层结构** | 自由输入后无法靠分类路由，必须分层兜底 |
| **校准句话术** | 去掉「60 分」这个数字 | 让它不依赖具体理由，能适配任意借口 |
| **满分申请制** | **申请（付费门槛）→ 承诺（绑定交付时间）** | 原设计惩罚了追求卓越，背离理念 |
| **精力点定位** | 收窄：只管"做几件"，不管"做多好" | 防止机制变成对质量的惩罚 |

---

## 零、一条价值观澄清（重要）

**60 分主义不是反卓越。**

- 追求完美本身不是病
- 「因为追求完美，所以不开始」才是病

因此产品对"想做到 100 分的人"的态度必须是**肯定**，不能是收费、设障或扣预算。任何让用户觉得"这个 App 在阻止我变好"的设计，都站到了理念的对面。

产品唯一要管的是：**完美必须有终点。**

## 一、核心机制

### 机制 01｜出发前那一问（自由输入版）

**交互**：
```
明早 7:00 · 健身 · 第 4 天

今天你大概会用什么理由不去？

[ 写下来，一句话就行　　　　　]

　　　　**[ 我去了 ]**

　　说出理由　·　今天确实不去
```

**设计要点**：

1. **理由完全自由输入，不给选项**。用户心里那团东西可能是"反正没人看""我今天就是不想动""做这个有什么意义"，这些无法做成选项，而它们的粗糙度本身就是最有价值的信息
2. **"我去了"是绝对主按钮**，最大、最显眼，且不要求先填任何东西
3. **输入框只允许一句话**（硬限制一行），防止完美主义者在"描述自己的理由"上再次完美主义
4. **「说不出理由」必须是显眼入口，不是兜底**

**「说不出理由」的处理**（可能是全产品最狠的一句）：
> 那今天没有理由，只有惯性。

不给用户任何可辩论的东西——你没理由，你只是没动。

---

### 机制 02｜假选项校准（产品的心脏，话术已升级）

**交互**：填完理由后，界面只回一句，然后回到行动按钮：

> 你在比较「状态最好时能做到的」和「今天什么都不做」。
> 但今天真实的选择是「今天能做到的那个版本」和「0」。

**为什么升级**：原版写死了「60 分的效果 vs 100 分的效果」，一旦用户写"我膝盖疼"就对不上了。新版把它抽象成**选择结构**的陈述，与具体理由无关，因此可以永远出现、永远成立。

**设计意图**：完美主义的全部论证，都建立在一个**不存在的选项**上——"要么做到最好，要么不做"。产品不鼓励用户，只负责**把被删掉的第三个选项放回桌面**。

**防坑**：
- 禁止任何打气话术（"你可以的""坚持一下"）。必须是**逻辑陈述**，语气像帮你算账，不像教练喊话
- 一句话说完，不解释原理、不上课，立刻给行动入口
- 这句话是产品的稳定底座，**不依赖 AI 理解理由内容**，任何情况下都必须出现

---

### 机制 03｜三层回应结构（解决自由输入后"然后呢"）

| 层级 | 内容 | 依赖 | 备注 |
|---|---|---|---|
| **第 1 层** | 固定校准句 | 无（纯文本） | 永远出现，产品的稳定底座 |
| **第 2 层** | 射程外的最小动作 | 需理解理由 | 见下方降级策略 |
| **第 3 层** | 理由存入个人借口库 | 无（原文存储） | 长期形成用户专属库 |

**第 2 层的降级策略（成本控制关键）**：

- **冷启动**：规则库匹配（条件不足型 / 结果无价值型 / 冲突型 / 身体信号型）
- **热启动**：复用用户历史——同类理由上次他用了什么最小动作、是否行动成功，这次还推那个
- **有模型能力时**：实时生成"它管不到的事"

> 建议：MVP 只做"规则库 + 历史复用"，**先不上大模型**。理由很简单——个人用户的理由类型高度重复，用两周就收敛了，不需要模型。

**最小动作的筛选铁律**：
> 这个动作，能不能被刚才那个理由否掉？否不掉，它就是对的。

示例：

| 用户理由 | 它管不到的事 |
|---|---|
| 太累，练了效果不好 | 穿鞋，下楼走一圈 |
| 膝盖疼 | 拉伸十分钟 |
| 方案没想周全 | 写 3 条要点发给一个人 |
| 状态不好做不好 | 打开文档，改一句话 |

---

### 机制 04｜事后证词（最锋利的一击，不变）

**数据采集**：每次计划到点后的当晚或次日，一次点击：
> 早上那个决定，现在你怎么看？　[ 庆幸没去 ]　[ 有点后悔 ]　[ 想不起来了 ]

**举证时机**：同一句理由（原文相似）第 3 / 5 / 8 次出现时，不是每次。

**举论文案**：
> 「太累，练了没效果」这句话，你今年说过 9 次。
> 其中 7 次，你当晚认为该去。

**为什么这是全产品最有威力的一击**：它不是打气，是举证。**而且证据是用户自己提供的原话**，无从反驳。

**防坑**：
- 必须节制，只在节点触发，保持稀有分量
- 只陈述次数和事实，禁止任何评价（"你看你又这样"绝对不能说）
- 证据库对用户完全开放，包括对他有利的记录

---

### 机制 05｜满分承诺制（原"满分申请制"改造）

**旧设计（已废弃）**：想做到 100 分需申请，并弹出代价"这一下花掉全部精力点，另外 4 件事今天做不了"。
**废弃原因**：这是对追求卓越收税，会让产品变成审判工具，背离理念。

**新设计**：用户表达"这次我想做到 100 分"时——

> 好，那就别交 60 分的版本。
> 你打算什么时候把它交出来？
>
> 　[ 今晚 ]　[ 明早 ]　[ 自己定一个时间 ]

**只加一个约束：交付时间。不加代价、不扣预算、不限制做别的。**

**设计意图**：完美主义真正的病根不是"想做好"，是**不设终点**——它可以做到无限好，所以永远不算完成。给它一个截止时间，不是在限制它，是把"完美"从一个无期徒刑改成一个有期限的项目。

**鼓励的措辞原则**：先肯定，再问时间。绝对不能出现"但是""不过"这类转折词开头。

## 二、辅助机制

### 保留
- **60 分不是评分系统**：产品内不出现任何针对质量的分数字段
- **想做池 vs 今日池**：想做池无上限（收纳欲望），今日池硬上限 3 件（隔绝欲望）
- **精力点（定位已收窄）**：只管"今天做几件"，**绝不用于惩罚质量**。做 1 件 60 分的事 = 1 点，与它做得多好无关
- **封箱交付**：交付后只读，只能新建下一版
- **借口档案（月度）**：回顾"最常用的三个理由 + 次数"，不说教，只呈现

### 新增
- **个人借口库**：用户历次输入的理由原文自动归档，形成专属词表。这是"预置库覆盖不全"的根治方案
- **记录入口极简**：写计划不要求分类、优先级、时间。记录本身也会完美主义，入口只能是随手记

## 三、指标体系（沿用 v0.2）

**北极星**：被推翻的借口数 / 周（产生"不去了"念头后仍然行动的次数）

**核心诊断**：预测偏差率（事先预判"做了没用"，事后认为该去的比例）

**健康 / 反向指标**：
| 指标 | 警戒线 |
|---|---|
| 拦截触达 → 行动转化率 | 长期 <30% 说明文案或时机有问题 |
| 通知关闭率 | >20% 必须立刻降温 |
| 自由输入完成率 | 填理由的比例过低，说明输入成本仍太高 |
| 「说不出理由」占比 | 异常高说明用户还没准备好面对，需要降门槛 |

**不做**：完成质量评分、完成度百分比、评级、排行榜。

## 四、MVP 范围（v0.3 收敛版）

一条链路，五个动作：

1. 写下一个计划（一句话，可带时间）
2. 到点触发那一问（自由输入框 + 我去了 + 说不出理由）
3. 填了理由 → 固定校准句 + 一条"它管不到的事" + 行动按钮
4. 当晚一问：那个决定现在怎么看
5. 同类理由第 3 次出现 → 亮出证词

**技术选型建议**：不上大模型。理由库用规则 + 历史复用即可，成本几乎为零，效果对个人用户足够。

**MVP 唯一验证问题**：7 天后，"被推翻的借口数"是否大于 0。如果是 0，问题在触发时机或那句校准话术。

---

## 五、待确认问题

1. **触发时机**：靠用户预设时间，还是行为探测？前者轻但覆盖率低，后者强但涉及隐私
2. **"身体信号"的放行标准**：发烧、疼痛、连续失眠应直接放行且不带评判。这条线的判定标准由谁定？——这是产品伦理的关键分界
3. **校准句是否要适配"冲突型"理由**（"今天要赶作业"）：这不是条件不足，硬套校准句会让人觉得被抬杠。是否需要第二套话术？
4. **证词功能默认开还是默认关**：力度很大，默认开体验强但可能吓退用户
5. **载体**：小程序最快验证，但拦截类产品高度依赖推送权限
