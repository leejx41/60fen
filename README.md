# 60 分 · 执行力 App（前端）

「60 分」是一个只问“今天做不做”的单机执行力 App。当前仓库是前端实现：React + TypeScript + Vite，数据落在 IndexedDB，无后端、无账号。

主应用视觉以 Stitch 原型（暖琥珀、纸感、大圆角、柔阴影、照片、Material Symbols）为基准；首次引导单独采用 Quiet Editorial 的纸白 + 深绿 + 衬线编辑风，与主应用形成反差。文案和业务规则以 `60分执行力App-PRD-v1.0.md` 为准，已删除 Stitch 中 PRD 未定义的加戏内容（统计百分比、英文顶栏、周日期条、记录 tab、产品解释段、自动返回等）。

## 运行

需要 Node 22 LTS（本项目在 Node v22.23.4 上验证）。

```bash
npm install
npm run dev
```

打开 `http://127.0.0.1:5173`。

本机没有全局 Node 时，工作区内的便携版可这样运行：

```powershell
$env:Path = "C:\Users\Lenovo\Downloads\60\.tools\node-v22.23.4-win-x64;" + $env:Path
npm run dev
```

常用命令：

```bash
npm run lint       # ESLint，零 warning
npm run typecheck  # tsc --noEmit
npm test           # Vitest（30 个测试）
npm run build      # tsc + vite build
npm run preview    # 预览生产构建
```

## 已实现范围

### 页面与交互

| 路由 | 页面 | 说明 |
| --- | --- | --- |
| `#/onboarding` | 首次引导 | 四屏；可跳过；重放用 `#/onboarding/replay`，不改任何记录 |
| `#/today` | 今日池 | 按时间升序；行内「满分」→ 100；超载提示每天一次；设置入口 |
| `#/pool` | 想做池 | 不显示时间；「今天做」补时间后移入今日池 |
| `#/settings` | 设置 | 参考容量、事后证词开关、到点提醒、再看一遍引导、关于；开发工具仅在 DEV 可见 |
| `#/intercept/:id` | 拦截卡 | 自由输入或四个分支入口；固定「我去了」；无关闭按钮 |
| `#/branch/:id/:branch` | 分支页 | branch 为 A/B/C/D；A 原话 → 证词 → 校准 → 降档；B 一句放回；C 当日放行；D 不追问 + 降档 |
| `#/acted/:id` | 已行动 | 你去了。→ 删除线原话 → 今年第 N 次；无自动返回 |
| `#/night/:id` | 当晚一问 | 21:00 后仅对 A/D 且未行动；一次点击；可跳过且不记录 |

### 业务规则

- 今日池只接受“今天 + 具体时间”；想做池只收标题，移入今日池必须补时间。
- 今日池无硬上限；参考容量 R 取近 7 日完成件数的中位数（至少 3 天有记录），否则用首次引导自填；超载只中性提示一次，不阻断。
- 今日池严格按时间升序；已满分项不挪位、不可重复标记。
- 自由理由走 A 路径，但 `branch="A"` 且 `reason_key` 为归一化原话，绝不写成 `tag:A`。
- 证词卡只在同一 `reason_key` 第 3/5/8 次出现；标签用「这个理由」，原话用「这句话」；统计不足 3 次不展示。
- 当晚一问只问 A/D 且 `action_taken=false` 的记录；B/C、已行动、普通未响应都不问；「这次不说了」不落库。
- 已行动页只在写过理由时显示删除线和「今年第 N 次」；直接点「我去了」不显示计数，也不进入当晚一问。
- 满分反馈固定为「100 分。／这次你做得很好。」，不参与任何指标。
- 全流程无质量评分、完成度、评级、排行榜、得分、连续天数、逾期标签或催促文案。

### 首次引导

- 首次启动进入四屏引导；右上角「跳过」随时可用。
- 正常看完后弹参考容量引导；跳过引导则同时跳过参考容量，不再弹超载提示。
- 设置页「再看一遍引导」只重放，不修改 `onboarded`、参考容量或任何记录。
- 老版本数据库升级时，已 `onboarded` 的记录自动补齐新字段，不会被新流程二次打断。

### 触发策略

Web 端后台定时器不可靠，所以：

1. 应用打开时每 15 秒检查一次已到期、且当天没有拦截记录的计划，立即补拦截；多张到期按计划时间最早优先。
2. 只在今日池/想做池/设置等普通页面扫描；引导、拦截、分支、夜问、参考容量弹层期间只更新时间，不写入拦截记录，避免“已经入库但没展示”把计划吞掉。选中候选后再次确认页面，才创建拦截并跳转。
3. 21:00 后、在今日池页面时检查当晚一问候选；页面隐藏时不偷偷跳转，等回到前台再补。
4. 页面隐藏且用户开启「到点提醒」、浏览器已授权时，发一条系统通知；当天同一计划只发一次。应用回到前台仍走第 1 条补拦截，通知只是 best-effort，不保证后台常驻。
5. 生产构建注册 Service Worker，缓存应用壳、首屏 JS/CSS 与字体，可离线打开；开发环境不注册，避免 HMR 读到旧模块。

## 演示数据与调试

**生产环境不写演示数据。** `seedIfNeeded` 在 `import.meta.env.DEV` 为 false 时直接 no-op，第一次打开只会经历四屏引导，首页是空的，所有计划都由用户自己写。生产构建也不会显示调试入口。

开发环境仍会在首次打开时种入样例，方便检查完整界面：今天 4 件事（07:00 已完成，18:00/20:00/21:30 待做）、前 3 天各 3 条完成记录、想做池 1 条。参考容量中位数因此为 3，首页会显示「今天第 4 件…」。若在引导里点「跳过」，参考容量也一并跳过，首页不再出现超载提示。

设置页底部「开发工具」仅在 `import.meta.env.DEV` 下出现：

- 预览拦截卡
- 快进到下一件事
- 重置演示数据

生产构建会隐藏这些入口。设置页正常区域的「再看一遍引导」在生产环境也可用。

## 部署

生产构建是纯静态 `app/dist/`，用 Cloudflare Pages 的 Git 集成部署。完整步骤、缓存头、验收清单和回滚方式见 [DEPLOY.md](./DEPLOY.md)。

- 构建命令：`npm run build`
- 输出目录：`app/dist`
- Node：22（`.nvmrc`，CI 与 `package.json` 的 `engines` 已同步）
- `public/_headers` 已配置 `/`、`/index.html`、`/sw.js`、manifest no-cache，`/assets/*` 一年 immutable；`/*` 只保留安全头，不设 `Cache-Control`，避免 Cloudflare 多规则拼接后把 assets 变成 no-cache
- 应用使用 hash 路由，不需要 SPA 重写规则
- 设置页「关于」显示构建版本，用于发布后确认真机拿到的是新版本
- Service Worker 强制验收：部署新版本后，刷新或重开应用必须看到新的「版本」时间；看不到就按 DEPLOY.md 的回滚步骤先移除 SW

## 已知取舍

- 演示数据只在开发环境种入；生产环境 `seedIfNeeded` 是 no-op，首启为空库，避免让试用者看到不是自己写的内容。
- 引导页是绿色 Quiet Editorial，主应用是琥珀 Stitch 风；这是刻意保留的视觉反差，不随主应用主题切换。
- 原生 `<input type="time">` 在 Chrome 聚焦时会显示系统蓝色分段；已去掉自动聚焦，仍保留原生选择器以保证可用性。
- 系统通知是 best-effort，依赖浏览器权限与页面是否仍存活；不保证后台常驻。通知只在页面隐藏时发，普通页/关闭状态点击后补拦截。
- Service Worker 缓存是应用壳级：首次在线加载后会缓存首屏 JS/CSS 与字体，离线刷新可用。缓存键目前为 `v3`，后续静态资源大改时需递增版本。
- 未做多张到期拦截的队列 UI，当前按最早计划逐张进入。
- P2「借口档案（月度回顾）」与「封箱交付」未实现；封箱在 PRD 里只有名称、没有定义，等试用反馈后再评估，不排进本轮。
- AI 代码审查按约定未执行；以上均为本地自检结果。
