## 2. 关键决策详述

### D-01 核心诊断：对手不是懒，是被自己说服

**选择空间**：把拖延当作"缺动力" / 当作"被自己的论证说服"

**为什么选后者**：用户原话是"我用完美当借口**说服**自己不去行动"。关键词是说服。一个被说服的人不缺动力，缺的是**有人检验他的论证**。

**这个诊断决定了一切**：
- 如果对手是懒 → 应该做激励、打卡、提醒
- 如果对手是被说服 → 只能做**拆解论证**

**推论**：打气、鸡汤、连续天数、成就徽章，全部无效——它们默认用户缺动力。

**对应 PRD**：1.1–1.3

---

### D-02 60 分不做成评分系统

**选择空间**：引入评分制 / 只做「许可证」和「预算」

**为什么**：完美主义者拿到任何评分工具，第一天就会开始争取「稳定 60 分以上」，**考核焦虑原封不动搬进新工具，内耗换了场地继续发生**。

**结论**：产品内不出现任何针对质量的分数字段。「60 分」只以两种形态存在——建任务时的**下限声明**、以及选做几件事时的**预算**。

**对应 PRD**：1.5 ③

---

### D-03 假选项校准是产品心脏

**决策**：核心那句话是——「你在比较 X 60 分的效果和 X 100 分的效果。但今天真实的选择是 X 60 分的效果和 0。」

**为什么它是心脏**：完美主义的全部论证，都建立在一个**不存在的选项**上——"要么做到最好，要么不做"。产品不需要鼓励用户，只需要**把被删掉的第三个选项放回桌面**。

**一个曾经反复的决策**：这句话该不该把「60 分」抽象成"状态最好时能做到的"？

**最终结论：不抽象。** 因为这句话每次出现都在**定义产品名**。用户第 50 次看到它，才真正理解"60 分"是什么意思。它是品牌资产，不是文案。抽象掉数字，等于把名字的定义权交出去。

**对应 PRD**：7.3

---

### D-04 最小动作切「射程」，不切「时间」

**曾经的选择**：60 秒启动门（只做 60 秒，到点可停）

**为什么否掉**：它假设阻力来自**行动门槛**。但真实阻力来自**用户已经完成了自我说服**——对一个被说服的人，倒计时无效。

**替代方案**：每个借口都有**覆盖范围**。「练了效果不好」只覆盖"训练"，不覆盖"穿鞋出门"。所以解法不是降低时间门槛，而是**把动作切到借口的射程之外**。

**给用户的判断标准**：*这个动作，能不能被刚才那个理由否掉？否不掉，它就是对的。*

**对应 PRD**：7.3 / 7.6

---

### D-05 最小动作在创建时预写，不上实时 AI

**选择空间**：实时 AI 生成 / 用户预写 / 任务类型模板库

**为什么不上实时 AI**：**最脆弱的那个时刻最不能有等待、网络和失败。** 他刚想说"算了"，让他在那儿转两秒等模型返回，人就走了。

**选预写的关键洞察**：**最小动作由「任务」决定，不由「理由」决定。** 健身的最小动作永远是"穿鞋出门"，不管理由写着累、没睡好、还是不想动。所以不需要理解理由。

**一句话**：*这一刻最清醒的人，为最脆弱的那个时刻做准备。*

**对应 PRD**：7.3 / 7.6

---

### D-06 理由自由输入，用分组标题说明关系

**曾经的选择**：从预置选项里挑

**为什么否掉**：预置理由的问题不是覆盖不全，而是**替用户说话**。用户心里那团东西可能是"反正没人看""做这件事有什么意义"，这些做不成选项，而它们的粗糙度本身就是信息。

**踩过的坑（重要）**：把输入框和四个入口平铺在同一屏、没有分组标题时，用户会产生**三种互斥的解读**：

- 直接选？
- 只写？
- 写完再点选项分类？

**三种都说得通，就是这个设计失败了。**

**最终解法**：两个分组标题「用你自己的话说」/「或者，挑一句最像的」充当说明书，不再额外加解释行。并且——**写了理由直接进拆解页，不再让他分类**。

**对应 PRD**：7.2

---

### D-07 路径与归属必须分离

**踩过的坑**：为了让用户少点一次，规定"写理由就走分支 A"。然后顺手把这条规则延伸到了数据归属——给一个写「1111111」的用户，展示了「我怕今天做不好」的历史统计。

**结论**：两个概念必须是两个字段。

| 字段 | 记什么 |
|---|---|
| `branch` | 走了哪条**处理路径** |
| `reasonKey` | 这条理由**归谁**（`tag:A` 或归一化原话） |

写自由理由的人：`branch = 'A'`（要进拆解页），但 `reasonKey` **绝不等于** `'tag:A'`。

**一句话教训**：**省一次点击的优化，绝不能穿透到数据层。交互简化属于 UI，归属属于事实。**

**对应 PRD**：7.3；技术方案 4.2

---

### D-08 证词：双指纹、3/5/8 门槛、结果完整呈现

**三个子决策**：

1. **双指纹**：点标签看标签历史（措辞用「这个理由」），写原话看原话**精确重复**（措辞用「这句话」，不做语义相似度）。**不足 3 次不展示证词卡**——宁可不说，不能说一句他没说过的。

2. **门槛 3/5/8 次**：每次都展示会变成唠叨。保持稀有，才有分量。

3. **完整呈现**：不只报"你错了 7 次"，而是「其中 7 次你后来觉得其实该去，另外 2 次你觉得幸好没去」。只报错的次数是单方面控诉，用户会本能抵触。**自己得出的结论才有效。**

**一句话原则**：**证词的力量来自真实，不来自煽动。**

**对应 PRD**：7.3

---

### D-09 当晚一问只问「被完美主义留下的决定」

**曾经的范围**：所有有拦截记录的计划

**收窄过程**（两次）：
1. 先发现对**已行动**的计划还在问，而三个选项全是"没去"的语境 → 排除已行动
2. 再发现对**身体不舒服**也问 → 排除分支 B/C

**为什么**：分支 C 那一屏产品自己说的是「今天就别去了。这不是借口。」**既然已经判定"这不是需要检验的决定"，晚上再回来问"庆幸没去还是有点后悔"，就是背弃承诺。**

**一句话**：**证词只用来检验「被完美主义留下的决定」，不用来检验「合理的放行」。**

**推论**：产品的行为气质是——它只在"可能被借口留下的那一类决定"上出现；合理的放行和已经完成的事，它都该彻底消失。

**对应 PRD**：7.8

---

### D-10 满分主动认领，不询问、不收费、不打折

**三次演变**：

| 版本 | 方案 | 为什么被否 |
|---|---|---|
| v0.2 | 满分申请制：想做 100 分要申请，并显示代价（花光精力点、其他事做不了） | **对追求卓越收税**，让产品变成审判工具 |
| v0.4 | 改成承诺制：那你要什么时候交？ | 语气像在逼用户 |
| **最终** | **计划页一个轻量入口「满分」，用户主动认领** | — |

**为什么最终选主动认领**：**刚做完事的人被问"想做到几分"，本质上还是在给他派任务；做完之后自己回计划点一下，那是他自己的判断。前者是考核，后者是自由。**

**反馈措辞的坑**：曾写「100 分。你本来可以只交 60 分的。」——本意是肯定超额付出，实际把 60 分设成了参照系，等于给成就打折。**改成「100 分。这次你做得很好。」两句，没有任何转折、任何补充。**

**由此产生原则④**：60 分是**底线**，不是**目标**。

**对应 PRD**：7.7b；1.5 ④

---

### D-11 今日池不设硬上限，用参考容量做一次提示

**三次演变**：定死 3 件 → 可配 1–6 件 → **无上限 + 参考容量一次提示**

**为什么最终取消上限**：用「件事数」当限制维度本身是粗的。**一个大任务拆成六个步骤算 1 件还是 6 件？上限拦住的往往是写得认真的人，而不是真正超载的人。**

**替代方案**：超载时出现一行字「今天第 7 件。你最近一周实际做完的是 3.2 件。」——不拦、不弹窗、每日仅一次、不用警告色。

**为什么这比标语有力**：不是产品告诉用户"太多了"，而是**把他自己的数字摆出来让他自己判断**。标语第三天就会隐形，数字不会。

**对应 PRD**：7.9

---

### D-12 两个池子的创建表单必须不同

**决策**：今日池必填时间，想做池**不问时间**。

**为什么**：想做池一旦要求填时间，它就不叫"想做"了，**叫压着期限的待办**。它存在的意义就是收纳那些还没有期限的念头。

**推论出的模型**：**今日池 = 今天；想做池 = 今天以外的一切（包括明天）。**

**对应 PRD**：7.1

---

### D-13 不做后端

**选择空间**：自建后端 / BaaS（Supabase 等）/ 纯本地

**为什么选纯本地**（四用户试用期）：

| 需求 | 是否需要后端 |
|---|---|
| 每人独立使用 | 不需要，浏览器天然隔离 |
| 换设备继续用 | 两周试用期不是真需求 |
| 作者看试用者数据 | 想要，但**其实不该看** |
| 数据不丢 | 唯一真风险，用导出缓解 |

**换来的一句话**：**"你的数据只在你自己手机上，我看不到。"** 这句话显著提高别人愿意试用的概率。

**接口预留**：`repo.ts` 从第一天就写成 async，未来换 Supabase 只改这一个文件。

**对应 PRD**：技术栈锁定 v1.0

---

### D-14 UI 是舞台，不是演员

**决策**：暖白纸、暖黑字、0.5px 细线、一个墨绿、零图标、零阴影、全部左对齐。

**推导链**：产品的价值几乎全在文案上 → **UI 如果抢戏，产品就毁了** → 舞台该是"安静、笃定、有纸感"。

**为什么不追潮流**：这份规范只用了两个不会过时的东西——**排版和留白**。追潮流的东西过五年就是某个年代的化石。

**对应 PRD**：UI 设计规范 v1.0

---

### D-15 首次引导：点击推进、无配乐、不在首页做 tips

**选择空间**：入场动画（自动播放） / 四屏点击推进 / 不做引导

**为什么做**：不做的话，新人会以为这是个待办清单，而这个产品的机制（到点拦截）需要他理解才能用起来。

**三个子决策**：

1. **点击按钮推进，不自动播放**——这一条决定它是"引导"还是"灌输"。用户掌控节奏，它就不算说教。
   **修正（v2.4）**：最初设计成"点击屏幕任意位置推进"，但屏 3 有两个可点的切换标签，整屏可点会导致**用户点标签时连带跳屏**，那一屏最关键的东西就没体验到。改为底部明确按钮。
   **推论出的通则**：全屏可点只在"这一屏没有任何可点元素"时才安全。任何一个可点元素出现，就必须有明确的行动按钮。

2. **不做配乐**——三个理由：浏览器禁自动播放音频会造成音画错位；产品调性建立在"安静"上，配乐会把它变成宣传片；用户可能在通勤/深夜打开，突然出声是冒犯。
   **替代方案：氛围靠节奏实现**——文字出现间隔、屏间停顿、过渡时长，这些"时间上的呼吸"就是氛围。

3. **不在首页做新手 tips**——首页只有三个元素，没有需要教的；且 tips 弹框会挡住「+ 添加」，用户第一次进来最想做的是加一件事。
   **真正需要说明的是第一次拦截卡**（用户会想"这算考核吗"），所以只在那里加一行：「说实话就行，它不会评价你。」

**文案打磨的一课**：
第一版改写把"你总是担心"换成"你想把它做好"，善意有了但**触动没了**。因为**触动来自精确，不来自温柔**——「条件不够完美」「计划还不周全」这两个具体细节才是戳人的地方。

但有一条线要守住：**说中 ≠ 指责**。区别在于有没有评价对错：
- 指责：「你为什么执行得这么慢」（你是缺点）
- 说中：「你在等一个能拿满分的时刻」（描述，不评价）

**对应 PRD**：7.0 / 7.2

### D-16 第一版视觉采用暖琥珀方案，暂不执行 UI 规范 v1.0

**决策**：主应用采用「暖琥珀 + 纸感 + 大圆角 + 柔阴影 + 照片 + Material Symbols 图标」；首次引导采用「纸白 + 深绿 + 衬线编辑风」。

**为什么**：产品负责人与开发沟通后确认该方案，优先保证第一版能快速上线、验证核心机制。视觉改造的成本高于当期收益。

**保留的判断**：D-14 的核心不是"必须零装饰"，而是**"UI 不该抢文案的戏"**。这一条依然有效——无论用什么视觉，只要界面开始用装饰争夺注意力，就是在违背它。

**已知张力（记录在案）**：
1. **引导与主应用是两套视觉语言**，用户看完四屏引导点「开始」会经历风格突变。是否造成断裂感，待试用反馈验证。
2. 大圆角 + 柔阴影 + 图标 + 照片，是当前生成式设计的高频特征。是否给人"通用模板感"，待试用反馈验证。

**什么条件下重启这个决策**：
- 试用者出现「记不住这个 App 长什么样」「感觉像普通待办工具」类反馈
- 或引导页与首页的跳转被反馈为"像换了个产品"

届时按 `UI设计规范-v1.0.md` 的零装饰方向改造，该文档原文已完整保留。

## 3. 黑名单：被否掉的方案

> **这张表比保留的方案更值钱。** 它防的是"三个月后有人（包括你）重新提出同一个想法"。

### 3.1 机制类

| 被否方案 | 否掉原因 | 什么条件下可以重启讨论 |
|---|---|---|
| **精力点 5 点制**（做几件事消耗几点） | 给"想做到满分"设置代价 = 对卓越收税，违反原则② | 不重启。预算可以量化，标准不能量化 |
| **60 秒启动门** | 治的是启动难度，不治"已被自己说服" | 若试用数据显示用户"想动但迟迟不开始"占比高，可局部引入 |
| **满分申请制**（含代价提示 / 时间问句） | 分别在施压和逼问 | 不重启 |
| **预置理由选项**（只能选不能写） | 替用户说话，覆盖不了真实 | 不重启。可作为输入辅助（点一下填进输入框），但不能替代输入 |
| **今日池硬性件数上限** | 拦错了对象，拦住写得认真的人 | 若超载提示连续一周没让任何人减过件数，可考虑引入软约束 |
| **强制分类用户理由** | 多一层摩擦，且分类会污染表达 | 不重启 |
| **封箱 / 版本号 / 废牌等辅助机制** | 不属于核心链路，第一版不做 | 试用期后再评估 |
| **逾期天数 / 连续天数 / 徽章 / 等级** | 逾期是审判，连续是打卡 | 永不重启（违反原则②③） |
| **质量评分 / 完成度 / 排行榜** | 违反原则③ | 永不重启 |
| **实时 AI 生成最小动作** | 最脆弱的时刻最不能有等待和失败 | 若出现"用户普遍不预写降档动作"且模型延迟降到 200ms 内 |

### 3.2 交互类

| 被否方案 | 否掉原因 | 重启条件 |
|---|---|---|
| **二次确认弹窗** | 违反原则②，主按钮必须一次点成功 | 永不重启 |
| **操作成功 toast** | 用户不需要知道系统记录成功 | 永不重启 |
| **加载态 / 骨架屏** | 没有网络请求 | 接了后端之后 |
| **新手引导流程** | 增加摩擦 | 若试用者普遍不知道从哪开始 |
| **用产品逻辑解释给用户听**（如"今晚不会有人来问你…只留给没去的人"） | 用户不需要知道我们的推送规则 | 永不重启 |
| **常驻理念标语** | 第三天就隐形，且会从提醒退化成教训 | 永不重启。理念只在首次引导末屏和月度回顾出现，各一次 |

### 3.3 技术类

| 被否方案 | 否掉原因 | 重启条件 |
|---|---|---|
| **Next.js / Nuxt** | 纯客户端应用，SSR 概念全是负担 | 永不重启 |
| **Redux / MobX** | 状态量太小 | 永不重启 |
| **Tailwind** | 需要学类名体系，10 个界面用不上 | 永不重启 |
| **UI 组件库**（Ant Design 等） | 视觉极简且高度定制，库的样式是负担 | 永不重启 |
| **React Router** | 流程性界面不该允许自由跳转 | 若要支持深链接分享（当前无此需求） |
| **dayjs / moment** | 所有时间都是 HH:mm / YYYY-MM-DD 字符串 | 若引入跨时区或复杂日期计算 |
| **自建合并队列** | O(n²) 验证成本，GitHub 有现成功能 | 永不重启 |
| **测试覆盖率门禁** | 覆盖率是给大团队流动用的指标 | 永不重启。只测六条业务规则 |
| **重型 SAST / 独立安全岗** | 纯前端本地应用，安全面极窄 | 接入后端之后 |

## 4. 四条原则是怎么来的

这四条不是一开始就有的，每一条都是踩坑之后补上的。

| 原则 | 由什么催生 |
|---|---|
| **① 60 分主义不是反卓越** | 设计出"满分申请制"，让用户为追求完美付出代价——站到了理念对面 |
| **② 绝不施压** | 出现"卡了三天""第 4 天"这类状态标签，以及各种代价提示 |
| **③ 可数资源，不可数质量** | 最初想给任务打分，发现问题比不打分更糟 |
| **④ 60 分是底线，不是目标** | 满分反馈写成「你本来可以只交 60 分的」，把 60 分变成了参照系 |

**共同点**：四条都是**产品差点变成审判工具**的时候被逼出来的。

这也是判断新需求的快捷方式：**这个改动让用户更容易开始行动，还是让他多了一道坎？** 多一道坎，就是错的方向——哪怕它看起来更规范。
