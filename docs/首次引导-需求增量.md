# 首次引导 · 需求增量说明

> **这份文档是给开发用的增量需求，不是全量需求。**
> 已有功能不动，只新增以下内容。
> 全量需求仍以 PRD v2.2 为准。

---

## 0. 一句话说明

新增一个只在**第一次打开应用**时出现的四屏引导，用于说明产品理念。之后可通过设置页重看。

---

## 1. 改动范围（只碰这三处）

| # | 改动 | 文件 |
|---|---|---|
| 1 | 新增引导屏组件 | 新建 `app/src/screens/Onboarding.tsx` |
| 2 | 路由/状态机加一个 view | 已有 view 枚举里新增 `'onboarding'` |

---

## 2. 启动逻辑

```
应用启动
  ↓
读取 settings
  ↓
onboarded === false ?
  ├── 是 → 进入 'onboarding'（四屏引导）
  └── 否 → 进入 'home'
```

引导结束后（无论看完还是跳过）：
- 写入 `settings.onboarded = true`
- 切到 `'home'`

**注意**：跳过也算已看过，不再出现。但设置页的「再看一遍」可以随时重放，重放**不修改** `onboarded`。

## 3. 四屏文案与视觉

### 通用规则

| 项 | 规格 |
|---|---|
| 背景 | `--bg`（暖白 #FBFAF7） |
| 文字 | `--ink`（暖黑 #1C1B18） |
| 字号 | 主文案 17px / 500，行高 1.9 |
| 对齐 | **左对齐**，左右内边距 32px |
| 位置 | 内容整体垂直居中偏上（约屏幕 38% 处） |
| 跳过按钮 | 右上角，11.5px，`--ink-3`，文案「跳过」 |
| **前进按钮（屏 1–3）** | 底部居中，**描边次按钮**：44px 高、宽度自适应（左右 padding 32px）、圆角 9px、边框 `--line`、文字 `--ink-2`，文案「继续」 |
| **前进按钮（屏 4）** | 同一位置，改**实心主按钮**（背景 `--accent`、白字），文案「开始」 |
| 按钮出现时机 | 该屏内容全部出现后 400ms，`opacity 0→1` |
| **推进方式** | **只有点击前进按钮才推进**。点击屏幕其他区域**不响应**。**不自动播放**。**不支持滑动** |
| 切换动效 | 当前屏 `opacity 1→0`（200ms），下一屏 `opacity 0→1` + `translateY(6px→0)`（280ms） |

---

### 屏 1

```
每天都有很多事想做。
但总有一些，
一直停在“想做”。
```

**视觉**：三行依次淡入，每行间隔 350ms。最后一行「想做」用引号包裹，正常字重。

---

### 屏 2

```
不是因为你懒。

是因为你在等——
等条件再好一点，
等计划再周全一点，
等自己有把握一点。

而那个时刻一直没来。
你只是，一直在准备开始。
```

**视觉**：分两组出现，中间留大间距（32px）。

- 第一组：「不是因为你懒。」单独一行，出现后停 400ms
- 第二组：三个「等」依次出现（每个间隔 250ms），然后停 600ms
- 第三组：「而那个时刻一直没来。／你只是，一直在准备开始。」

**这一屏是引导的情绪核心，节奏不要赶。**

---

### 屏 3（含交互，必须实现）

**文字**（先出现）：

```
有没有算过这笔账：
```

**然后出现精力条**（5 个格子）：

```
[▓][▓][▓][▓][▓]
```

**三个阶段**：

| 阶段 | 表现 | 时长 |
|---|---|---|
| 1. 初始 | 5 格全部浅灰（`#EDEAE2`） | — |
| 2. 第一态 | 第 1 格被一个墨绿色块**占满 5 格宽度**（即一个长条），下方文字「一件做到 100 分」 | 停留 1.2 秒 |
| 3. 第二态 | 过渡成 5 个独立墨绿格，下方文字「五件各 60 分」 | 停留 1.2 秒 |

**过渡**：`width` 变化用 `transition: width .45s cubic-bezier(.4,0,.2,1)`（或 flex 比例变化）。

**交互（必须做）**：

自动播完两态之后，格子下方出现两个可点击的小标签：

```
[ 一件做到 100 分 ]  [ 五件各 60 分 ]
```

- 当前态高亮（`--accent` 实底 + 白字）
- 未选中为透明底 + `--line` 描边
- 点击可在两态之间反复切换，带动画
- **这是整个引导唯一需要用户动手的地方，不要省**

**文字**（切换后可一直显示）：

```
一件做到 100 分的力气，
够你做五件 60 分的。
```

---

### 屏 4

```
所以 60 分就够了。

不是因为它容易，
是因为它现在就能开始。
```

**视觉**：三行依次出现，最后一行出现后 400ms，底部浮出主按钮 `[ 开始 ]`。

点「开始」→ 切 `'home'`。

## 4. 跳过规则

- 「跳过」按钮**在屏 1 就可见**，任何一屏都可点
- 点击后：立即写入 `onboarded = true`，切 `'home'`，**不做二次确认**
- 不允许"必须看完才能用"

## 5. 设置页新增一项

位置：设置页最后一项。

```
再看一遍引导        ›
```

点击 → 进入 `'onboarding'`，从屏 1 开始。看完或跳过后回到设置页（**不是 home**）。

## 6. ❌ 不要做的事

这些看起来是"顺手优化"，但会破坏产品：

| 不要做 | 原因 |
|---|---|
| ❌ 不要加配乐 / 音效 | 浏览器拦截自动播放；且会破坏"安静"的产品气质 |
| ❌ 不要自动播放，必须用户点击按钮推进 | 自动播放是灌输，点击推进是引导 |
| ❌ 不要做成"点击屏幕任意位置推进" | 屏 3 有可点的切换标签，整屏可点会导致点标签时跳屏 |
| ❌ 不要在进度指示上加"1/4"这类文字 | 会让人焦虑"还有三屏" |
| ❌ 不要加"上一步"按钮 | 四屏很短，回退反而添乱 |
| ❌ 不要在首页加新手 tips 气泡 | 首页只有三个元素，没有需要教的 |
| ❌ 不要重构 Home / Intercept 等已有组件 | 这是纯新增需求，不该改动已有逻辑 |
| ❌ 不要引入动画库（Framer Motion 等） | 只有 opacity 和 width 在变，纯 CSS 够用 |
| ❌ 不要把文案硬编码在组件里 | 全部进 `copy/strings.ts` |

## 7. 另一处小改动（独立于引导，但一起提）

**第一次拦截卡出现时，在问句下方加一行说明：**

```
说实话就行，它不会评价你。
```

规则：
- 样式：11.5px，`--ink-3`，无边框、无底色
- **只在用户第一次看到拦截卡时显示**（用一个 `settings.firstInterceptSeen` 或复用已有字段）
- 第二次之后不出现
- 不改变拦截卡任何现有交互

---

## 8. 验收标准

- [ ] 首次打开进入引导，第二屏起不再出现
- [ ] 只有点击底部前进按钮才推进；点击屏幕其他区域不响应
- [ ] **屏 3 点击两个切换标签时，不会连带推进到下一屏**
- [ ] 屏 1–3 按钮为描边样式，屏 4 为实心主按钮，位置一致
- [ ] 「跳过」在第一屏就可见，点击直接进首页，无二次确认
- [ ] 屏 3 自动过渡两态后，两个标签可反复点击切换，动画不卡
- [ ] 屏 4「开始」→ 直接进首页
- [ ] 设置页「再看一遍引导」可重放，看完回设置页
- [ ] 首次拦截卡出现时显示那行说明，第二次不再显示
- [ ] 全流程无配乐、无音效
- [ ] 所有文案来自 `copy/strings.ts`
- [ ] 未引入任何新的动画/音频依赖
